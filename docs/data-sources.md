# Data sources and sample status

## Area comparison and provisional test area

**Jezero** has a particularly convenient documented path for a first sample: a USGS Astrogeology STAC collection of MRO/CTX stereo DTMs, each with related orthorectified image assets, plus published Jezero-specific CTX and HiRISE map products. The Mars 2020 landing region also has extensive image coverage. **Gale** has extensive public Curiosity-era map resources and rover imagery, but products we found quickly include mosaics with differing spatial registration; one Caltech page specifically warns that some Gale products are not registered to the global THEMIS IR mosaic and may offset from MOLA and rover paths. This is not a complete inventory comparison, but Jezero currently looks simpler for testing co-located layers.

**Provisional sample area:** 77.44–77.49°E, 18.42–18.47°N around the Perseverance landing point (18.4446°N, 77.4509°E; planetocentric, positive-east longitude and ocentric latitude). This is a search AOI, not a confirmed DTM footprint. Its purpose is to include the landing point in the catalog query; the script must still identify a real intersecting DTM footprint before any sample is claimed.

**Updated science scenario:** a hypothetical Jezero sedimentary rock core for later organic-molecule / potential-biosignature analysis, motivated by Perseverance sample 25, **Sapphire Canyon**, a 6.2 cm sedimentary core from Cheyava Falls in Bright Angel (sealed 21 July 2024, Sol 1215). SHERLOC detected organic compounds in the source rock; their origin is not determined by this finding alone. The Bright Angel sample is geographically outside this small CTX crop; the app marker is illustrative and must not be called Sapphire Canyon or registered to its sample coordinates. NASA sample catalog: [Mars Rock Samples](https://science.nasa.gov/mission/mars-2020-perseverance/mars-rock-samples/); research context: [Murphy et al. 2025](https://doi.org/10.1038/s41586-025-09413-0).

### CTX terrain and orthophoto characteristics from documentation

- **Instrument/product:** MRO Context Camera stereo-derived CTX DTM, generated with the Ames Stereo Pipeline; related orthorectified images are generated from the corresponding stereo data.
- **Collection metadata and credit:** [STAC collection record](https://stac.astrogeology.usgs.gov/api/collections/mro_ctx_controlled_usgs_dtms) identifies NASA as producer and USGS as processor/host, gives CC0-1.0, and links DOI 10.5066/P9JKVWR3. Suggested citation recorded there: Laura et al. (2023), *Mars Reconnaissance Orbiter (MRO) Context Camera (CTX) orthoimage generated using Ames stereo pipeline derived digital terrain models*.
- **Coverage and registration:** the STAC item footprint overlaps the selected 77.44–77.49°E, 18.42–18.47°N ROI. The three output crops have identical Mars CRS, bounds, 148×148 transforms and NoData masks. This confirms grid overlap for these files, not rover-scale geolocation accuracy.
- **Observation time:** the item field `datetime=2023-04-18T12:00:00Z` is a collection/catalog timestamp, not either image acquisition time. The two input CTX observations were acquired 2008-04-05 00:01:32 UTC and 2008-05-31 12:10:26 UTC (rounded to seconds) per the Jezero CTX mosaic source table. This stereo pair therefore combines different dates; it is not a single-time snapshot.
- **NoData:** the shared mask contains 295 of 21,904 cells (1.35%). Raw source NoData was −32767; the crop-conversion script writes NaN outside the ROI and at masked source cells. These cells are omitted from the terrain surface, not rendered as holes in relief. NoData means there is no product value, not unsafe ground. No interpolation is assumed.
- **Intersection diagnostic:** the ASP docs define error-image values as ray separation in metres. ASP's paper explains that this is indirect, relative self-consistency: high triangulation error can indicate matching/camera-model issues, while low error does not prove the terrain is accurate. Do not title it “uncertainty” or “accuracy”.
- **Resolution:** in this sample, DTM and orthoimage have the same 20.162955 m/pixel grid. This does not demonstrate fine image detail over a coarser height grid. Collection-level CTX postings do not substitute for this item's measured resolution. Typical CTX DTM vertical precision is 3–5 m according to USGS docs; the crop is too coarse for small obstacles or astronaut safety decisions.
- **Use / credit:** CTX ARD collection metadata reports CC0-1.0 and DOI 10.5066/P9JKVWR3. Cite Laura et al. (2023), the two CTX input IDs, and USGS Astrogeology. The CacheCam photo credit is NASA/JPL-Caltech; keep its link and caption.

## Reproducible sample procedure

Run `python scripts/fetch_mars_samples.py --bbox 77.44 18.42 77.49 18.47` in an environment with Python 3.10+, `rasterio`, `pyproj`, `numpy`, `matplotlib`, and network access. This existing run selected item `P18_007925_1987_XN_18N282W__P19_008650_1987_XI_18N282W` and wrote the three actual asset URLs above. It downloaded bounded COG crops and produced the preview. Re-export the compact demo data with `MPLCONFIGDIR=/tmp/martian-map-mpl .venv/bin/python scripts/build_demo_data.py`; this checks grid/CRS/transform and NoData-mask equality, rounds displayed heights to whole metres, converts the ortho only to an explicitly display-only grayscale stretch, and stores the intersection diagnostic in centimetres for display. The 337 KB JSON under `public/data/` is a small, documented derivative; raw GeoTIFFs stay ignored. The NASA CacheCam reference image is loaded separately from its official photojournal asset, never georegistered to the CTX site.

## What is and is not verified

The local `data/raw/jezero/` files were verified with the existing `.venv` (rasterio 1.5.2, pyproj 3.8.0, numpy 2.5.4, matplotlib 3.11.2). The source assets were retrieved by the user's Ubuntu run; actual downloaded raster checks succeeded locally: shapes/CRS/transforms/NoData and values are in `sample-metadata.json` and the GeoTIFFs. The three raster grids line up exactly; the DTM's NoData mask is 1.35%. The preview is visually inspectable, but its 3 layers are one MRO/CTX stereo product, not three NASA missions. The NASA Mars 2020 witness-tube reference adds a second mission's documented sampling-control example; it is not a local environmental observation or astronaut protocol. For the MEDA test below, ordinary sandbox DNS resolution failed; a bounded, approved HTTPS retrieval obtained the cited public PDS files. The exact target location and scenario routes remain manually selected. No wind field, contamination transport estimate, contact probability, safety threshold, or contamination-reduction claim is produced.

## Geographic extent and activity scenario (verified versus illustrative)

The current raster's affine transform and 148×148 dimensions give its pixel-edge bounds as approximately **77.43977–77.49012°E, 18.41999–18.47033°N** (Mars 2015 ocentric equirectangular, IAU:49910). This is the lander-area CTX crop; it is not a Bright Angel DTM. Scenario places reuse raster positions already present in the prototype: start S `(row 126, col 16)`, site A `(16,137)`, and sample target B `(76,78)`. All three are `illustrative_scenario` positions, not Perseverance observations. Their row/column positions and current straight route length (about 4.99 km at the raster posting) are supplied to the app by `public/scenario.js`; the same route is used by all plans.

NASA's sample record identifies Sapphire Canyon as sample 25, collected from Cheyava Falls in Bright Angel and sealed on Sol 1215. It does not georegister that sample onto this CTX crop. A NASA Planetary Science Division map gives Perseverance's **June 21, 2024 rover location** as 77.48205542°E, 18.49070°N, north of this crop's 18.47033°N edge; that is an earlier rover position, **not the sample's July 21 coordinates**. We therefore do not move a marker to that rover point, present either scenario point as Sapphire Canyon, or claim a co-located MRO + Mars 2020 map. [NASA Mars Rock Samples](https://science.nasa.gov/mission/mars-2020-perseverance/mars-rock-samples/) · [NASA PSD update / Perseverance map](https://assets.science.nasa.gov/content/dam/science/cds/researchers/nac/pac/2025/2%20-%20PSD%20Update%20July%202024_TAGGED.pdf).

**Mission use in this prototype:** MRO/CTX supplies the georeferenced surface image, DTM, and stereo diagnostic. Mars 2020/Perseverance supplies documented sample-science context and the NASA robotic sample-control precedent, neither georeferenced into this map. MEDA Sol 36 is retained only as a separate historical weather figure. No verified Perseverance science target is presently used as a mapped activity point; A/B are explicitly hypothetical work locations. This is a remaining spatial-context gap relative to a multi-mission mapped-scene requirement.

## Event-history implementation

`public/scenario.js` supplies the three ordered plans on the same S→A→B route. `public/contact-model.js` calculates per-object source reachability from directed, explicitly assumed events and returns event-linked explanations. Plan C omits only the stated G1→T2 contact; it is not a general isolation control. The app renders route geometry as a solid route line and shows contact provenance in the timeline/history panel, not as wind/particle movement on the map. Event inputs are human scenario assumptions; the map does not measure contact or material.

## Temperature and radiation products considered (not downloaded here)

MEDA archives calibrated air-temperature products (ATS), calibrated and derived thermal-infrared products (TIRS), and calibrated radiation/dust products (RDS, including UV-to-near-IR channels). A temperature series could eventually support a defined thermal-exposure or sample-handling decision, but that needs a specific activity time/location plus a suit/crew thermal model or sample-specific temperature response. Without that, it is an extra reading. UV/visible/IR radiometry could bound photochemical exposure only with spectral response, shade/dust/surface shielding, duration and contaminant or organic degradation data. Those inputs are absent, so no temperature/radiation product is implemented. MEDA RDS optical UV/visible/IR measurements are not ionizing dose: Curiosity's RAD measures high-energy particles such as protons/ions, neutrons and gamma rays ([NASA instrument description](https://science.nasa.gov/mission/msl-curiosity/science-instruments/)). Curiosity is also in Gale Crater, so its RAD data are not local Jezero measurements.

**Interpretive boundary:** MRO and Mars 2020 provide different context (orbital geography versus rover sample/analysis/environmental evidence), but only MRO/CTX is currently a georeferenced layer in the scene. The current scene does **not** satisfy a claim of a co-located, multi-mission mapped layer. No dataset above supplies a measured human Mars-sample transfer value.

### Multiple-mission integration status

The scene's **georeferenced map layers currently come from one orbiter/instrument family: MRO/CTX**. Mars 2020/Perseverance contributes a relevant but unregistered witness-tube method image, not a second mapped layer. The current prototype therefore does not yet demonstrate a co-located, multi-mission layered map. The challenge asks for data from multiple NASA science missions; before claiming that requirement is satisfied, add a suitable second mission product with documented footprint, coordinate system, acquisition time, resolution and registration, or state clearly that this is still a prototype gap. Do not overlay an unverified tile or Gale rover image just to increase the mission count.
